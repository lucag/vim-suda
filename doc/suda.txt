INTRODUCTION					*suda-introduction*

*suda* is a plugin to read or write files with "sudo" command.

This plugin was built while ":w !sudo tee % > /dev/null" trick does not work
on Neovim.

https://github.com/neovim/neovim/issues/1716

This plugin is strongly inspired by sudo.vim but the interfaces was
aggressively modified for modern Vim script.

For Windows users, install mattn/sudo command to enable this plugin.

https://github.com/mattn/sudo

Make sure that the following shows 1.
>
	: echo executable('sudo')
<
Before each read or write, |suda| asks sudo whether a credential is already
cached ("sudo -n -v"). If one is, the command runs without a password prompt.
Otherwise |suda| asks for the password with |g:suda#prompt| and passes it to
sudo on stdin. The privileged command always runs exactly once: a wrong
password or a failing command is reported with its own error message and is
not retried. Answer the prompt with an empty string (<Esc> or <CR>) to cancel;
|suda| then shows "[suda] cancelled" and runs nothing.

Whether a credential cached outside the editor (for example by running sudo
in your shell), or by an earlier read or write, is honoured depends on sudo's
"timestamp_type" setting and on the process that runs sudo. See sudoers(5).
With sudo 1.8.21 or newer, a global timestamp shares the credential everywhere:
>
        Defaults timestamp_type = global
<
Please make sure this is in line with your security requirements.

On Windows, and when |g:suda#executable| is not sudo-compatible, the command
runs once with no credential check and no password prompt.

						*suda-terminal-client*
On Neovim 0.12 or newer (not Windows), |suda| asks the Terminal Client, the
"nvim" process attached to your terminal, to start each sudo step. sudo then
runs in the process session and on the terminal of the Host Shell, the shell
that launched the editor, so it shares the Host Shell's Credential Scope: a
credential cached by "sudo -v" in the Host Shell is used by the editor, and a
password typed in the editor is honoured back in the Host Shell. This works
with the default "timestamp_type", for sudo-rs and for sudo.ws.

The password prompt stays in the editor. Only the sudo arguments, the editor's
environment and working directory, the password (once, if needed) and the
exit code and error message pass between the editor and the Terminal Client.
File contents do not: the Terminal Client writes what |:SudaRead| reads
straight into the editor's temporary file, and |:SudaWrite| hands sudo a
temporary file to copy.

						*suda-fallback*
|suda| delegates only to a UI that has a terminal on both stdin and stdout,
whose process started the editor's server (so it runs on the same host), and
that answers the editor's request. A GUI, a remote UI ("nvim --remote-ui")
and headless use fail this check, and so does Neovim 0.10 and 0.11, whose
Terminal Client cannot answer. Then sudo is started by the editor's server
process itself, without a shell and without detaching. The Credential Scope
is then shared across reads and writes within the Editor Session, but not
with the Host Shell. A remote UI never runs sudo on the host it runs on.
A |g:suda#executable| that is not sudo-compatible always runs from the
server: without sudo's "-n" or "-S" it could prompt on your terminal while
the editor waits. If the Terminal Client stops answering in the middle of an
operation, |suda| reports an error instead of running the step again in the
server, because the step may already have run.

With 'verbose' set, |suda| logs which process runs sudo and why, followed by
each sudo command line (never the password): >
	:set verbose=1
	:SudaRead /etc/shadow
	[suda] running sudo from the Terminal Client (UI on channel 1, process 4242)
	[suda] sudo -n -v
	[suda] sudo -n -- cat /etc/shadow
<	or, for example: >
	[suda] running sudo from the server: no UI is attached
<
On Vim, on Neovim older than 0.10 and on Windows, sudo runs through
|systemlist()|, which starts every step in a new process session, so whether
a credential is reused depends on sudo's configuration (see above).

USAGE						*suda-usage*

Use |:SudaRead| to open unreadable files like:
>
	" Re-open a current file with sudo
	:SudaRead

	" Open /etc/sudoers with sudo
	:SudaRead /etc/sudoers
<
Or use |:SudaWrite| to write unwritable files like:
>
	" Forcedly save a current file with sudo
	:SudaWrite

	" Write contents to /etc/profile with sudo
	:SudaWrite /etc/profile
<
Or directly use "suda://" prefix on |read|, |edit|, |write|, or |saveas| like:
>
	" Open a current file with sudo
	:e suda://%

	" Save a current file with sudo
	:w suda://%

	" Edit /etc/sudoers
	:e suda:///etc/sudoers

	" Read /etc/sudoers (insert content under the cursor)
	:r suda:///etc/sudoers

	" Read /etc/sudoers at the end
	:$r suda:///etc/sudoers

	" Write contents to /etc/profile
	:w suda:///etc/profile

	" Save contents to /etc/profile
	:saveas suda:///etc/profile
<
You can change the prompt string by |g:suda#prompt| like:
>
	" 'Password' in french
	let g:suda#prompt = 'Mot de passe: '
<
-----------------------------------------------------------------------------
SMART-EDIT					*suda-usage-smart-edit*

When |g:suda_smart_edit| is true, suda automatically switch a buffer name when
the target file is not readable or writable.

In short,
>
	$ vim /etc/hosts
<
or
>
	:e /etc/shadow
<
Will open "suda:///etc/hosts" or "suda:///etc/shadow" instead of "/etc/hosts"
or "/etc/shadow" because that files are not writable or not readable.

INTERFACE					*suda-interface*

-----------------------------------------------------------------------------
COMMAND						*suda-interface-command*

						*:SudaRead*
:SudaRead [{path}]
	Edit the {path} or re-open the current buffer with sudo.
	It is equivalent to ":e suda://{path}"

						*:SudaWrite*
:SudaWrite [{path}]
	Save content of the current buffer or save it to the {path} with sudo.
	It is equivalent to ":w suda://{path}"

-----------------------------------------------------------------------------
FUNCTION					*suda-interface-function*

						*suda#system()*
suda#system({cmd} [, {input}])
	Run {cmd}, a |List| of arguments, with "sudo", passing the optional
	{input} string on stdin. A password is asked for only if needed (see
	|suda-introduction|).
	On success, returns the command's stdout. On failure, returns its
	stderr instead (never stdout). Lines are joined with "\n" and NUL
	bytes are removed. |v:shell_error| is set to the command's exit code
	in both cases.
	Throws "cancelled" when the password prompt is answered with an empty
	string.

						*suda#systemlist()*
suda#systemlist({cmd} [, {input}])
	Like |suda#system()| but returns a |List| of lines, with NUL bytes
	replaced by "\n", like |systemlist()|.

						*suda#read()*
suda#read({expr} [, {options}])
	Insert contents of {expr} below the cursor.
	The following attributes are available on {options}

	"cmdarg"	|v:cmdarg| passed to |read| command
	"range"		{range} passed to |read| command

	A tempfile and |read| command is used to load the content of the
	{expr} internally.

						*suda#write()*
suda#write({expr} [, {options}])
	Write contents of current buffer to {expr}.
	The following attributes are available on {options}

	"cmdarg"	|v:cmdarg| passed to |write| command
	"cmdbang"	|v:cmdbang|| passed to |write| command
	"range"		{range} passed to |write| command

	A tempfile and |write| command is used to dump the content of the
	buffer internally.

-----------------------------------------------------------------------------
VARIABLE					*suda-interface-variable*

*g:suda#executable*
	The privilege-escalation tool, as a |String| or a |List|.
	A String is one program and is never split on spaces, so a path such
	as "/opt/my tools/sudo" works. A List is an argv prefix: a program
	followed by extra arguments, for example: >
		let g:suda#executable = ['sudo', '-E']
<	The tool is sudo-compatible when the basename of the program (the
	String, or the first List item) is "sudo", "sudo-rs" or "sudo.ws",
	also given as a full path. Only then does suda add sudo flags and
	"--" before the command, check for a cached credential, and ask for a
	password.
	Any other tool (for example "doas") runs as the executable plus the
	command, with no flags and no password prompt; suda never sends it a
	password. Such a tool always runs non-interactively, as sudo does with
	|g:suda#noninteractive| set, so it needs a passwordless setup.
	Note: a String is no longer split on spaces. If you used a String with
	arguments, such as "sudo -E", use a List instead: ['sudo', '-E'].
	Default: "sudo"

*g:suda#noninteractive*
	If set, suda never prompts for a password and does not check for a
	cached credential: it only runs the command non-interactively
	("sudo -n"), which fails if sudo needs a password. It is supposed to
	support a setup with passwordless sudo.
	Use with care.
	Default: 0

*g:suda#prompt*
	A prompt string used to ask password.
	Default: "Password: "

*g:suda_smart_edit*
	If set, an |autocmd| is created that performs a heuristic check on
	every buffer and decides whether to replace it with a suda buffer.
	The check is done only once for every buffer and it is designed to be
	optimized as possible so you shouldn't feel any slowdown when openning
	buffers.
	Default: 0
